# 医嘱撤销预测（Order Retraction Prediction）

> **一句话**：别人预测病人会怎么样，我们预测**下这条医嘱的医生会不会把它撤回来、多久之后撤、
> 是自己撤还是别人撤**。
>
> NUS **BN5212** 小组课程项目 · 数据：MIMIC-IV v3.1 · 全部代码、日志、指标、报告都在本仓库里。

---

## 1. 这个项目在做什么

在医院的电子医嘱系统（CPOE）里，医生下达一条医嘱之后，这条医嘱有可能被撤销——
可能是医生自己反应过来剂量开错了，也可能是药师复核时拦下来、或者交接班后接手的同事换了方案。
**每一次撤销，都意味着药房、护理、检验环节的一次返工。**

我们做的事：**在医嘱刚被下达的那一刻（t₀），预测它会不会被撤销、多久之后被撤、以及会被谁撤。**

这件事之所以能做，是因为 MIMIC-IV 的 `hosp.poe` 表里有一个**系统自带的显式指针**
`discontinued_by_poe_id`，直接指出「这条医嘱是被哪条医嘱撤销的」。
标签是白送的——不需要人工病历回顾，不需要代理指标。实测双向匹配率 **99.98%**。

### 核心想法：撤销不是一件事，是两件方向相反的事

| | 自撤（self-cancel） | 他撤（other-cancel） |
|---|---|---|
| 是谁 | 开单医生**自己**把它撤了 | **别人**把它撤了 |
| 含义 | 自我纠错 | 复核拦截 / 方案被覆盖 / 交接班改方案 |
| **实测时延** | **38.6% 在 1 小时内**，之后单调递减 | 只有 4.8% 在 1 小时内，**峰值在 6–24 小时** |

两者的 hazard 形状完全不是一回事。把它们**合并成一个「会不会被撤」的二分类**，
等于把两股方向相反的力叠在一起训练，梯度会互相抵消。

⇒ **预注册主张**：自撤 / 他撤分头建模再合成，优于直接训单头。
⇒ **预注册判据**：test 集上 `ΔAUPRC ≥ 0.01` 且按患者重抽的 bootstrap 95% CI 不含 0。
⇒ **不达标就如实报告。** 这是课程项目，不是刷榜；负结果照样写进报告。

详细方案见 [`docs/00_项目方案.md`](docs/00_项目方案.md)，接口规范见 [`docs/01_数据契约.md`](docs/01_数据契约.md)。

## 2.5 模型结果（test，5,183,024 条医嘱，正类率 20.35%）

| 模型 | AUROC | **AUPRC** | Brier | ECE | **C-index(td)** | AUPRC@24h | 自撤 | 他撤 |
|---|---|---|---|---|---|---|---|---|
| 基准率 | 0.500 | 0.2035 | 0.1621 | 0.0007 | 0.500 | 0.1397 | 0.0860 | 0.1156 |
| 逻辑回归 | 0.7802 | 0.5105 | 0.1544 | 0.1329 | 0.7525 | 0.3370 | 0.2267 | 0.3416 |
| LightGBM 单头 | 0.8077 | 0.5636 | 0.1241 | 0.0048 | 0.7480 | 0.3820 | 0.2009 | 0.3644 |
| LightGBM 双头 | 0.8044 | 0.5570 | 0.1250 | 0.0065 | 0.7867 | 0.3664 | 0.2814 | 0.4248 |
| LightGBM 三分类 | 0.8050 | 0.5607 | 0.1247 | 0.0065 | 0.7872 | 0.3700 | 0.2827 | 0.4274 |
| **Transformer 单头** | **0.8266** | **0.6009** | **0.1187** | 0.0038 | 0.7665 | 0.4090 | 0.2075 | 0.4025 |
| **Transformer 竞争风险头** | 0.8208 | 0.5801 | 0.1242 | 0.0304 | **0.8066** | **0.4458** | **0.2998** | **0.4608** |

两个冠军各管一摊：**预测「会不会被撤」** 是 Transformer 单头最好；
**预测「谁会撤、什么时候撤」** 是 Transformer 竞争风险头最好。

### 🔴 预注册主张：**在两个模型族上都被推翻**

| 对照 | ΔAUPRC | 95% CI（按患者重抽 1000 次） | 判据 ≥ +0.01 |
|---|---|---|---|
| LightGBM：双头 − 单头 | −0.0066 | [−0.0072, −0.0062] | ❌ |
| LightGBM：三分类 − 单头 | −0.0029 | [−0.0034, −0.0025] | ❌ |
| **Transformer：竞争风险头 − 单头**（同编码器、同预算，**只换最后一层**） | **−0.0208** | [−0.0214, −0.0202] | ❌ |

不但没达到 +0.01，**Δ 全是负的、CI 全部完全落在 0 左边**。
序列模型那一组是最干净的对照（同一份数据、同一个 8 层编码器、同样 3 个 epoch，
唯一差别是输出层），它输得**更多**。
⇒ 这不是某个实现的偶然，**是这个主张本身在场景 A 上不成立**。

作为尺度参照，同一套 bootstrap 下：
「LightGBM − 逻辑回归」= **+0.0532**，「Transformer 单头 − LightGBM 单头」= **+0.037**。
**换表示、换模型族的收益，是 cause 分解那点差异的一个数量级以上。**

### 但分解买到了单头**在结构上给不出**的东西

同一组干净对照里（Transformer，只换头）：

| | 单头 | 竞争风险头 | |
|---|---|---|---|
| AUPRC 自撤 | 0.2075 | **0.2998** | **+45%** |
| AUPRC 他撤 | 0.4025 | **0.4608** | **+14%** |
| C-index(td) | 0.7665 | **0.8066** | **+0.040** |

（这三项不是预注册判据，按事后发现标注。）

### 场景 B：把「携带反向效应的那个特征」放进模型，分解仍然没赢

支撑这个主张的反向效应来自 eMAR 的 `Not Given`，而它**不在场景 A 里**。
所以我们另做了一组 landmark 实验（τ=24h，入组 3842 万条，预测 (24h,48h] 内被撤）把它放进来：

```
Δ eMAR 的贡献（单头）    = +0.0214   CI [+0.0204, +0.0224]   ← eMAR 本身很有用
Δ eMAR 的贡献（三分类）  = +0.0210   CI [+0.0200, +0.0218]   ← 但对两个头一样有用
Δ 分头 − 单头（无 eMAR） = −0.0017   CI [−0.0024, −0.0010]
Δ 分头 − 单头（有 eMAR） = −0.0021   CI [−0.0029, −0.0014]   ← 没变好，略微更差
```

⇒ **机制假说被直接否证。** 原推理链是「存在方向相反的协变量效应 ⇒ 单头梯度抵消 ⇒ 分头更准」。
前件成立（`f_prov_prior_self_rate` 对自撤 +0.856 / 对他撤 −0.889，近乎完美反对称），
**后件不成立**——断掉的是中间那一步。

## 2.6 结论

在医嘱下达时刻预测它会不会被撤销是**可行**的（AUPRC 0.60 vs 随机线 0.20）。
但预注册的方法学主张**在四次独立检验下全部不成立**。真正有用的是另外三件事：

1. **换表示比换输出头重要一个数量级**（+0.037 / +0.053 vs −0.002~−0.021）；
2. **执行层 eMAR 事件有实质预测力**（+0.021，CI 不含 0）；
3. **竞争风险头买到的是「谁」和「何时」，不是「会不会」**——
   逐因 AUPRC 自撤 +45%、他撤 +14%、C-index +0.040，代价是合成预测让出约 0.02 AUPRC。
   如果产品形态是「这条医嘱大概率会在 6 小时内被**别人**撤掉」，那就必须用它。

完整分析、失败原因的三条拆解、**四个只有独立审计才抓得出来的缺陷**、
以及对立项时所引证据的自我修正，见 [`docs/04_结果报告.md`](docs/04_结果报告.md)。

## 3. 怎么复现

### 3.1 拿数据（这一步我们没法替你做）

MIMIC-IV 是 **PhysioNet 凭证数据**，DUA 禁止再分发。你需要自己：

1. 在 [PhysioNet](https://physionet.org/content/mimiciv/3.1/) 完成 CITI 培训并申请凭证；
2. 下载 MIMIC-IV v3.1；
3. 把压缩包路径填进 `configs/config.yaml` 的 `paths.mimic_zip`，或设环境变量 `MIMIC_IV_ZIP`。

**本仓库里没有任何患者数据**，`data/` 和 `checkpoints/` 都被 `.gitignore` 排除了。

### 3.2 装环境

```bash
pip install -r requirements.txt
# torch 请按自己的 CUDA 版本装，本机是 cu128：
# pip install torch --index-url https://download.pytorch.org/whl/cu128
```

### 3.3 按顺序跑

```bash
python src/s01_extract.py        # zip → parquet（不解压，流式读）      约 5 分钟
python src/s02_labels.py         # 指针 → 13 类竞争风险标签             约 1 分钟
python src/s03_features.py       # 场景 A 静态特征（含防泄漏滚动统计）
python src/s04_split.py          # 按 subject_id 确定性切分 80/10/10
python src/s05_baseline.py       # 基准率 / 逻辑回归 / LightGBM 单头与双头
python src/s06a_build_seq.py     # 构建医嘱序列
python src/s06_seq_model.py      # causal Transformer + 竞争风险头（GPU）
python src/s07_eval.py --compare lgbm_dual lgbm_single --split test   # 预注册主实验
python src/s08_figures.py        # 出图
```

每个脚本都会自动留下三份痕迹：
`logs/<步骤>.log`（运行日志）、`results/metrics/<步骤>.json`（聚合指标 + 环境指纹）、
`docs/02_实验记录.md`（一行摘要）。**脚本跑完不删。**

先跑小样本验证管线：`python src/s01_extract.py --smoke`。

## 6. 诚实的局限（会写进最终报告，不藏）

| # | 局限 |
|---|---|
| L1 | 「撤销」大量是**改剂量 / 改频次的修订**，不等于「医生反悔了」。技术措辞一律用 *discontinuation / revision* |
| L2 | `order_provider_id` 是**账号不是人**。「自撤」严格说是「同一账号撤的」 |
| L3 | 1.07% 的撤销因 provider 缺失无法判定自撤/他撤，被排除在 13 类损失之外（仍保留在二分类里） |
| L4 | `anchor_year_group` 只有 3 年一档，时间漂移分析的分辨率有限 |
| L5 | 本地 `icu.chartevents` 缺 28.3%、`hosp.emar_detail` 缺 34.4%，**全工程禁用这两张表** |
| L6 | MIMIC-IV 是**单中心**（BIDMC）数据，结论的外推性未经验证 |
