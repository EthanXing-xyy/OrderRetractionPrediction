# 数据契约（Data Contract）

> **这份文件是全工程唯一的接口规范。** 任何人（或 agent）写 `src/` 下的脚本，
> 都只按本文件约定的表名、列名、dtype、取值编码来读写，不去猜上一步产出了什么。
> 改契约 = 改所有下游，**改之前先在这里改，并在 `docs/02_实验记录.md` 留痕**。

全部中间产物落在 `Project/data/`（已被 `.gitignore` 排除，不进 GitHub）。
时间一律是 **epoch 秒（Int64）**，不是字符串、不是 datetime。

---

## 0. 全局约定

| 约定 | 内容 |
|---|---|
| **主键 `key`** | `key = subject_id * 2**24 + poe_seq`，int64。MIMIC 的 `poe_id` 形如 `"<subject_id>-<poe_seq>"`，等价但省 3 列长字符串。`poe_seq` 实测最大值远小于 2²⁴ = 16,777,216，`s01` 会断言校验。 |
| **时间单位** | 存 epoch 秒（Int64）；派生的「时长」列统一用**小时**（float32），列名以 `_h` 结尾。 |
| **缺失** | 整数列用 pandas `Int64`（可空），浮点列用 `NaN`，布尔列用 `bool`（不可空，缺失要先决定语义）。 |
| **禁用表** | `icu.chartevents`（本地副本缺 28.3%）、`hosp.emar_detail`（缺 34.4%）。**全工程不得读取。** |
| **禁用特征** | `drgcodes`（出院后计费标注 = 泄漏）、`discharge_location`/`hospital_expire_flag`（出院后才知道）、任何 `dischtime` 之后的信息。 |

## 2. `s02_labels.py` 的产物：`labels.parquet`

每条医嘱一行，与 `poe.parquet` 行数相同、顺序相同。

| 列 | dtype | 含义 |
|---|---|---|
| `key` | int64 | 主键，见 §0 |
| `subject_id` | int64 | 切分用（同一患者必须同侧） |
| `hadm_id` | Int64 | 可空（无住院号的医嘱不入队列） |
| `ordertime` | int64 | t₀，epoch 秒 |
| `y_disc` | bool | **H1**：是否被撤销（`discontinued_by_seq` 非空且指针可解析到实际存在的行） |
| `delay_h` | float32 | **H2**：撤销单 `ordertime` − 本单 `ordertime`，小时。未撤销为 `NaN` |
| `cause` | int8 | **H3**：`0`=未撤　`1`=自撤（撤销单与本单 `order_provider_id` 相同）　`2`=他撤　`3`=任一方 provider 缺失 |
| `censor_h` | float32 | 从 t₀ 到 `min(dischtime, deathtime)` 的小时数（删失时刻） |
| `in_cohort` | bool | 入队列：有 `hadm_id` + 能对上 admissions + `censor_h > 0` + 成人（`anchor_age >= 18`） |
| `t_bin` | int8 | `delay_h` 落进的离散桶，见 §2.1；未撤销为 `-1` |
| `censor_bin` | int8 | `censor_h` 落进的桶：删失发生在第几个桶，似然只算到这个桶 |
| `y13` | int8 | **主模型标签**，见 §2.2；不可用样本为 `-1` |

### 2.1 离散时间分桶（6 桶）

```
bin 0: (0, 1h]      bin 1: (1h, 6h]     bin 2: (6h, 24h]
bin 3: (24h, 72h]   bin 4: (72h, 7d]    bin 5: (7d, +inf)
```
边界（小时）：`[0, 1, 6, 24, 72, 168, inf]`，**左开右闭**。`delay_h <= 0` 的异常样本单独计数并排除。

### 2.2 13 类竞争风险编码 `y13`

```
y13 = 0                 到删失时刻仍未被撤销（censored / 存活）
y13 = 1 + t_bin         自撤，发生在第 t_bin 个桶      → 1..6
y13 = 7 + t_bin         他撤，发生在第 t_bin 个桶      → 7..12
y13 = -1                不参与竞争风险损失（cause==3 的 provider 缺失样本、delay_h<=0 的异常样本）
```
`cause==3`（约 1% 量级）**保留在 H1 二分类里**（它确实被撤了），但**排除在 13 类损失之外**，
因为不知道是自撤还是他撤。这一条要在报告里写明，并给出它占比。

### 2.3 ⚠ 不要从 `delay_h` 反推撤销时刻（踩过的坑，已修）

`delay_h` 是 **float32**，只用来分桶和报分位数。
**任何需要把撤销时刻拿去和别的时间戳做精确比较的地方，都必须用 `common.resolve_disc_time()`**
（它直接从指针取被撤销那一刻的整数 epoch 秒，全程不碰浮点）。

原因：反推 `t_disc = ordertime + delay_h * 3600` 有亚秒级误差，
而 **MIMIC 的时间戳是分钟粒度**，大量医嘱共享同一时刻，
亚秒误差恰好落在「t_disc 是否等于某条医嘱的 t₀」这个边界上，把比较结果翻过去。

实测代价（`src/t01_leak_test.py` 抓到的）：
- 「截至 t₀ 已发生的撤销数」在 **16.7%** 的行上差 1；
- 造出 **38 行**「已发生的撤销数 > 此前下达的医嘱数」这种逻辑上不可能的结果。

**这个缺陷在任何指标上都看不出来**——它不改变 AUPRC 的量级，只是悄悄把一个计数特征弄脏。
所以 `t01_leak_test.py` 不是可选项，改完特征工程必须重跑一遍。

### 2.4 删失的处理

离散时间竞争风险的似然：对每个样本，只在 `bin <= censor_bin` 的桶上计似然。
`censor_bin` 之后的桶是「看不到的未来」，不参与。这是 DeepHit 的离散时间版做法。

## 3. `s03_features.py` 的产物：`features.parquet`

每条医嘱一行，**只含 t₀ 时刻可得的信息**（场景 A）。用 `key` 与 `labels.parquet` 对齐。

| 组 | 列名前缀 | 说明 |
|---|---|---|
| 本单 | `f_order_type`, `f_order_subtype`, `f_transaction_type` | 类别（int16 编码，词表存 `data/vocab.json`） |
| 时间 | `f_hour`(0-23), `f_dow`(0-6), `f_since_admit_h`(float32) | t₀ 的小时/星期/距入院时长 |
| 医嘱属性 | `f_detail_*` | 由 `poe_detail` 透视得到的高频 `field_name`（取 top-K），值做类别编码 |
| 住院 | `f_admission_type`, `f_admission_location`, `f_insurance`, `f_careunit`, `f_curr_service` | 类别 |
| 人口学 | `f_gender`, `f_age_bin`, `f_anchor_year_group` | 类别 |
| 本次住院至今 | `f_n_prior_orders`, `f_prior_disc_rate`, `f_dt_prev_order_h` | **只用 t₀ 之前**的累积量 |
| 开单者 | `f_prov_n_prior`(分档), `f_prov_prior_disc_rate`, `f_prov_prior_self_rate` | **滚动统计，只用 t₀ 之前**；用全量统计就是泄漏 |

### 3.1 泄漏铁律（写特征时逐条对照）

1. **禁止**用 `discontinued_by_seq` / `discontinue_of_seq` 及其派生量。
2. **禁止**用 `order_status`（它的取值直接反映了这条医嘱最终的状态）。
3. 开单者与住院级的历史统计**必须是 t₀ 时刻的前缀累积**（按 `ordertime` 排序后 `cumsum` 再 `shift(1)`），
   不许用整条住院/整个数据集算出来的率。
4. 科室 `f_careunit` 取 `transfers` 中满足 `intime <= t0 < outtime` 的那一条，**不许**用住院期间的众数。
5. **禁止**任何 `dischtime` 之后的信息；`discharge_location`、`hospital_expire_flag`、`drgcodes` 一律不用。
6. 场景 A **禁止**用 `emar`（那是 t₀ 之后的执行事件）；`emar` 只在场景 B 用，且只取 `charttime <= t0 + τ` 的事件。

## 4. `s04_split.py` 的产物：`splits.parquet`

| 列 | dtype | 含义 |
|---|---|---|
| `subject_id` | int64 | |
| `split` | int8 | `0`=train `1`=val `2`=test，**按 subject_id 哈希切 80/10/10**，同一患者所有住院同侧 |
| `split_time` | int8 | 时间外推用：按 `anchor_year_group` 训早测晚，`0`=早期训练 `1`=晚期测试 |

## 5. 序列数据：`data/seq/`（`s06` 用）

主模型是 causal Transformer over order sequence：按 `hadm_id` 聚合、按 `ordertime` 升序，
切成定长 256 的块，**每个位置输出该位置那条医嘱的 13 类预测**（一次前向拿整段住院的预测）。

| 文件 | 内容 |
|---|---|
| `data/seq/<split>_tokens.npy` | int16/int32，shape `(n_block, 256, n_cat_field)`，类别特征的词表 id |
| `data/seq/<split>_num.npy` | float32，shape `(n_block, 256, n_num_field)`，数值特征（已标准化） |
| `data/seq/<split>_y13.npy` | int8，shape `(n_block, 256)`，`-1` 表示 padding 或不参与损失 |
| `data/seq/<split>_censorbin.npy` | int8，shape `(n_block, 256)` |
| `data/seq/meta.json` | 词表大小、字段顺序、标准化用的均值方差、块数 |

## 6. 指标输出：`results/metrics/*.json`

每个脚本写一份，文件名 = 脚本名。**只许写聚合量**，`common.save_metrics()` 会自动：
- 附上 `_env` 环境指纹（python / 包版本 / GPU / git commit），保证可复现；
- 过一遍 `assert_no_pii()`；
- **n < 10 的计数一律写成 `"<10"`**（用 `common.sup()`）。

主指标（`s07_eval.py` 统一计算，所有模型走同一套函数）：

| 指标 | 说明 |
|---|---|
| `auroc` / `auprc` | H1 任意撤销，**AUPRC 是主指标**（正类 20%，AUROC 会虚高） |
| `auprc_self` / `auprc_other` | 逐因：自撤、他撤各自的 AUPRC |
| `brier` / `ece` | 校准；配 10 桶可靠性曲线 |
| `cindex_td` | 时间依赖 C-index（竞争风险版） |
| `auprc@24h` | 24 小时内被撤销的预测 |
| `ΔAUPRC` + bootstrap 95% CI | **预注册主张**：双头（自撤/他撤）合成的任意撤销预测 − 单头直接训。判据：`ΔAUPRC >= 0.01` 且 CI 不含 0 |

所有 bootstrap **按 `subject_id` 重抽**（不是按行），1000 次。

### 6.1 四处口径的拍板（契约原先没写死，2026-09-21 定，之后不要再改来改去）

| # | 问题 | **定下的做法** | 理由 |
|---|---|---|---|
| 1 | `cindex_td` 的可比对子怎么抽 | **订单级均匀抽**：`i` 从 cause-k 的事件行均匀抽、`j` 从全部行均匀抽、**丢掉同患者对子**，默认抽 200 万对 | 这个模型的部署单位是**一条医嘱**（CPOE 里每下一单弹一次提示），不是一个病人。若改成「先抽患者再抽行」，等于给开单少的患者加权，那对应的是另一个问题（各患者间性能是否公平），不是我们要答的 |
| 2 | `auprc_self` / `auprc_other` 的负类 | one-vs-rest，且**把 `cause==3` 的 114,434 行整体剔除** | 不知道是谁撤的，就不能把它当成「不是自撤」。当负类是造假 |
| 3 | ECE 用等宽还是等频分桶 | **主表引等宽 ECE**（标准定义，能和文献比）；**可靠性曲线图用等频**（`p_disc` 集中在 0.2 附近，等宽分桶上半截几乎是空的，画出来看不出形状）。两者都写进 JSON | 一个要可比，一个要好看清楚，各取所长；只要在报告里标明哪张是哪种 |
| 4 | `s07_eval.py` 里置 `CUDA_VISIBLE_DEVICES=""` | **保留** | 防止 `env_fingerprint()` 的 `torch.cuda.is_available()` 去 6 GB 卡上开 CUDA context 抢显存。代价是 s07 的 `_env` 里没有 GPU 型号——无所谓，评测本来就不该用 GPU |

**bootstrap 必须报三个数**：`n_boot_requested` / `n_boot`（真正有效的次数）/ `n_boot_nonfinite`。
起因：按患者重抽时约 1/e 的患者权重为 0，分数最高那一段的累计权重就是 0，
precision 变成 `0/0` ⇒ 整条 AP 变 nan。实测端到端演练时 **1000 次里有 569 次返回 nan**，
若不报这三个数，置信区间会悄悄变成「残存那 431 次的分位数」而没人看得出来。

## 7. 预测输出契约：`results/preds/<模型名>_<split>.parquet`

> **这是模型与评测之间唯一的接口。** 有了它，任何模型（LR / LightGBM / GRU / Transformer）
> 都只负责「吐预测」，`s07_eval.py` 只负责「读预测算指标」，两边可以独立开发、独立替换。
> **模型脚本不许自己算指标**，一律调 `s07_eval` 里的函数，保证所有模型用的是同一把尺子。

| 列 | dtype | 含义 |
|---|---|---|
| `key` | int64 | 主键，与 `labels.parquet` 对齐 |
| `subject_id` | int64 | bootstrap 按患者重抽要用 |
| `p_disc` | float32 | **H1**：这条医嘱最终会被撤销的概率（任意 cause、任意时刻） |
| `p_self` | float32 | 最终被**自撤**的概率 |
| `p_other` | float32 | 最终被**他撤**的概率 |
| `p_disc_24h` | float32 | 24 h 内被撤销的概率（= 前 3 个桶的累积发生率） |
| `p13_0` … `p13_12` | float32 | 13 类的完整概率向量（可选；只有竞争风险头的模型有，基线可留空） |

约束：
- `p13_*` 若给出，必须**和为 1**（容差 1e-3）；`p_disc = 1 - p13_0`；
  `p_self = sum(p13_1..p13_6)`；`p_other = sum(p13_7..p13_12)`；
  `p_disc_24h = sum(p13_{1,2,3}) + sum(p13_{7,8,9})`（桶 0/1/2 = ≤1h、1-6h、6-24h）。
- 只在 `labels.in_cohort == True` 的行上出预测。
- `<split>` ∈ `{val, test}`。**训练集不出预测文件**（没用且占地方）。
- 模型名用小写下划线：`baserate` / `logreg` / `lgbm_single` / `lgbm_dual` / `gru` / `transformer_v0` / `transformer_cr`。

**预注册主实验**（方案 §3.1）就落在这个契约上：
`lgbm_dual`（分别训自撤头和他撤头，`p_disc = p_self + p_other - p_self*p_other` 或直接 `1-p13_0`）
对比 `lgbm_single`（直接训「会不会被撤」），比 `test` 上的 AUPRC。
判据：`ΔAUPRC >= 0.01` 且按 `subject_id` 重抽的 bootstrap 95% CI 不含 0。**不达标就如实写不达标。**
